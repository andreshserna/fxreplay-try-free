**3. Minor: what the repository says PostHog documents is not what PostHog documents.**

- Where: `src/server/analytics/sink.ts:36-39`, `docs/analytics-plan.md:142`, `docs/decisions/log.md:524-526`.
- The claim: a repeated uuid inside one request is dropped, and nothing is documented across requests.
- What PostHog says (posthog.com/docs/data/events, "Event deduplication", read 2026-11-20 UTC): events that share the same `uuid`, event name, distinct id and UTC date of timestamp are treated as duplicates and are de-duplicated eventually, during background ClickHouse merges, so duplicates may persist for a while before they are merged.

PostHog says a later copy "completely replaces the original", so a browser can now replace its own earlier browser events; server events are safe, as the collector refuses their names and the name is part of the key.
- Also: "every stored event's `uuid` equals its `event_id`" cannot be true of events stored before that release: the check was made for release `0c993dd` only.
- Not verified: it cannot see PostHog.
