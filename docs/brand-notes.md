# Brand notes

How this project implements the FX Replay brand kit, written for the design team that made
it. It covers the color tokens, the contrast audit, what we added, the scales, the fonts and
the logo files.

## What we received, and what we rebuilt

The kit's README lists `tokens/tokens.css`, `tokens/tokens.json` and a `source/` folder with
two PDFs. None of them was in the archive we received. It held the README, `brand-kit.html`
and three logo SVGs.

All 44 primitives and all 60 semantic mappings are present as data in `brand-kit.html`, so
the token files were rebuilt from it:

- `tokens/tokens.json` is the source, with every name unchanged.
  `scripts/kit/tokens-from-kit.mjs` builds it from the kit page and checks that the committed
  file still matches: 44 primitives, 60 semantic tokens.
- `tokens/tokens.css` is generated from the JSON. Primitives hold the literals and semantic
  tokens alias them, as the README describes.
- One naming rule gives every token its CSS name: the token's own name, lowercased, spaces to
  hyphens. `bg-primary` is `--bg-primary`.
- Product code may use semantic tokens only. A check runs after every edit and in CI and
  rejects literal colors and references to primitives.

## Your two open questions

**1. `btn-bg-primary-disabled` points at `blue-950`, which the scale does not define.**

The kit page falls back to `#000000`. On the `#030303` ground that is 1.01:1: a disabled
primary button disappears. Defining a `blue-950` would not help, because any blue darker than
`blue-900` (already 1.31:1 on the ground) is invisible on a ground this dark. On a dark-first
system, "disabled" cannot mean "darker".

Proposal: repoint the token to `dark-500`, the value `btn-bg-secondary-disabled` already
uses. The button keeps a visible shape (1.81:1), reads as inactive because it loses the brand
hue, and all button variants share one disabled look. Its label, `btn-text-disabled`, is
2.65:1 on that fill. WCAG exempts inactive controls from contrast minimums, but this is low
enough to be worth a look.

In this project the question does not arise: the submit button is never disabled. While a
request is in flight it stays on the active fill with a spinner and `aria-busy`, and errors
are reported instead of prevented. To keep `tokens.css` valid, the token aliases `dark-950`,
which has the value your page falls back to.

**2. `card-bg-translucent` is `dark-900` at 60% through `color-mix()`.**

`color-mix()` has been Baseline "widely available" since 2025-11-09 (Chrome and Edge 111,
Firefox 113, Safari 16.2; source: webstatus.dev, read 2026-11-18). That is this project's
browser target, so no fallback is emitted. A fallback would also mean writing a second,
literal copy of the color, which is what the token system exists to avoid.

## What we added

Eleven extension tokens, in `tokens/extensions.json` and `tokens/extensions.css`, kept apart
from the kit's files. Each aliases a value the kit already has. None introduces a color.

| Token | Value | Why | Before | After |
|---|---|---|---|---|
| `border-field` | `dark-200` | A form field's boundary needs 3:1. It is the value your outline button already uses | `border-tertiary` 1.81:1 | 3.81:1 on the ground, 3.66:1 on a `bg-secondary` fill |
| `border-field-error` | `error` | An error outline has to be seen. Always shown with an icon and a message | `border-error` 2.46:1 | 4.10:1 |
| `text-link` | `blue-500` | Body-size links on the ground need 4.5:1 | `text-brand` 4.02:1 | 5.26:1 |
| `card-text-link` | `blue-400` | Links inside `bg-tertiary` surfaces | `blue-500` 4.44:1 | 5.90:1 |
| `border-focus` | `blue-500` | Focus ring, 2px with a 2px offset, as your kit page draws it | Electric Blue 4.02:1 | 5.26:1 |
| `btn-border-primary` | `blue-500` | A 1px edge on the primary button while hovered or pressed, so it keeps its shape | Hover fill 1.69:1 and pressed fill 1.31:1 against the ground | The edge is 5.26:1 against the ground and 3.09:1 against the hover fill |

On the focus ring: your page uses Electric Blue, which passes 3:1 on the ground. We moved one
step lighter so the ring stays distinct from the Electric Blue button it surrounds.

Not changed, on purpose: Electric Blue as the primary CTA fill, and the dark ground.

The hover and pressed fills themselves are yours, unchanged. If you would rather not have the
edge, the alternative is to define lighter hover and pressed fills in the kit.

### The illustration's colors

The hero's replay illustration is an original drawing, not a product screenshot. Its colors
are five more aliases, so the drawing can be restyled from the token file:

| Token | Value | Used for |
|---|---|---|
| `chart-up` | `blue-600` (Electric Blue) | Rising candles, the played part of the timeline, the glow |
| `chart-down` | `neutral-200` | Falling candles |
| `chart-grid` | `dark-700` | Grid lines |
| `chart-future` | `dark-500` | Hatching over what has not been replayed yet |
| `chart-playhead` | `blue-500` | The playhead |

Candles are blue and near-white, not green and red. That keeps the picture inside your
palette, and it avoids coloring a simulated trade as good or bad on a page that must not
imply results. The drawing carries no text and no contrast requirement.

### Scales

The kit leaves sizing open, so the type, space and shape scales are ours:
`src/styles/scale.css`. Type is fluid between a 360px and a 1440px viewport, with no
breakpoints. Corners are 10px on controls and 12px on surfaces, inside the 9 to 12px your kit
page uses.

### Fonts

Lato and Nunito Sans are self-hosted from the Fontsource packages (SIL Open Font License):
three weights each, Latin subset, six files, only the heaviest Lato preloaded. The web build
of Lato is version 1.104, the one your kit page loads from Google Fonts. Desktop
distributions ship 2.015, which has slightly different metrics: a design tool with the
desktop version installed will not match the browser to the pixel.

## Questions for the design team

1. **The wordmark file draws every shape twice.** `FXReplayLogo.svg` holds 16 paths: 8 paths
   repeated, byte for byte. Your kit page's inline copy draws the 8 once. Is the doubling an
   export artifact?
2. **Each logo file wraps its paths in a `clipPath`** whose id would collide if the SVG were
   inlined twice on a page, and the wordmark's path coordinates reach about 0.15 px past the
   clip rectangle. Can the clip be dropped?
3. **The two-tone isotype** in your kit page's header (a blue outlined arrow and a light
   solid arrow) is not shipped as a file. Is it an approved lockup?
4. **Wordmark color.** The file is pure white. Your page draws the wordmark in `#F6F6F6` on
   dark and in white on blue. Which is canonical on the dark ground?
5. **CSS names of the three brand primitives** ("Electric Blue", "Black", "Accent"). Without
   `tokens.css` we cannot know them. We emit `--electric-blue`, `--black` and `--accent`. No
   semantic token points at any of them.
6. **`alternate`** is the only semantic token without its group's prefix. Is `bg-alternate`
   intended?
7. **Your kit page uses colors outside the tokens** (`#060606`, `#0b0b0b`, `#1c1c1c`,
   `#9a9a9a`). We map those surfaces to the nearest tokens, `bg-secondary` and
   `border-primary`. Should the palette gain those steps?
8. **There are no font files** in the kit, and the page loads a third family, JetBrains Mono,
   for its captions. We treat Lato and Nunito Sans as the brand's two families and do not
   ship the mono.

## The logo files

Used as shipped: the wordmark in the header and on the share image, the two isotypes as the
browser-tab icon (the white one where the browser's own interface is dark, the black one
where it is light). None is recolored, stretched or given an effect. The wordmark file is an
unminified export of 19.7 KB. It is served as it came. Optimizing it without altering a shape
is possible and was left alone, so the file in the repository is byte for byte yours.
